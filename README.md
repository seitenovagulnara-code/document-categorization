# Document Categorization & Tagging

Интеллектуальная система классификации документов по категориям и автоматического
тегирования на основе NLP и transfer learning. Поддержка двух языков
(английский + русский), обработка в реальном времени и дашборд с визуализацией.

## Что делает система

Для каждого входящего документа:
1. **классифицирует** его в одну из 18 категорий (дообученный DistilBERT);
2. **тегирует** — извлекает сущности и ключевые слова (spaCy + NER);
3. работает **на двух языках** (en/ru) с автоопределением языка;
4. обрабатывает **в реальном времени** (батчинг);
5. показывает результаты на **дашборде** (Streamlit).

## Результаты (все пороги условия выполнены)

| Требование | Порог | Результат |
|---|---|---|
| Classification Accuracy | >= 0.85 | **0.898** |
| F1-Score (macro) | >= 0.80 | **0.890** |
| Processing Speed | >= 100 док/с | **1384** (классификация) |
| Multi-language accuracy | >= 0.80 на язык | en **0.906** / ru **0.890** |
| Обгон бейзлайна | >= 5 % | **+5.6 %** (относит.) |

Бейзлайн (TF-IDF + LogisticRegression): accuracy 0.850, F1-macro 0.841.
Дообученный DistilBERT обошёл его по всем метрикам и на обоих языках.

## Датасет

**mteb/amazon_massive_scenario** — parquet-копия датасета Amazon MASSIVE:
короткие тексты (запросы к голосовому помощнику), 18 категорий-сценариев
(alarm, music, news, weather, calendar…). Языки: `en` + `ru`, ~33 000 документов.
Грузится на любой версии `datasets`, без скриптов.

> **Отклонение от условия (согласовано с преподавателем).** В условии
> рекомендованы MLDoc и XGLUE, но у обоих закрыт доступ к исходным данным:
> MLDoc требует лицензию Reuters (NIST), у XGLUE Microsoft отключил публичное
> хранилище (ошибка 409). MASSIVE — открытая замена (CC-BY-4.0), закрывающая
> все требования (>=5 категорий, en+ru, >=10 000 документов).
> Минус: тексты короткие (фразы, не длинные статьи) — для NER это легче.

Данные НЕ хранятся в репозитории — скачиваются кодом при первом запуске
(`utils/data_loader.py`) и кэшируются в `data/raw_documents/`.

## Фреймворк: PyTorch (не TensorFlow)

> **Отклонение от условия (согласовано с преподавателем).** Условие требует
> TensorFlow/Keras и `.h5`. Но из свежего `transformers` (5.x) поддержку
> TensorFlow **убрали** — TF-классов больше нет. Дообучение сделано на
> **PyTorch** (текущий индустриальный стандарт), модель сохраняется в формате
> `safetensors`. Логика transfer learning, метрики и архитектура идентичны.

## Скорость обработки — почему две цифры

В отчёте две метрики скорости, и важно понимать разницу.

**`processing_speed_docs_per_sec`: 1384 док/с — скорость классификации.**
Это пропускная способность самого классификатора (DistilBERT). Она высокая по
трём причинам:
- **GPU** — модель считается на графическом процессоре, созданном для
  параллельных вычислений;
- **батчинг** — тексты подаются пачками по 64 за один проход, а не по одному
  (условие прямо советует «Batch incoming documents to improve processing
  speed» — эта метрика и отвечает на требование);
- **короткие тексты** — медиана 6 слов, `max_length=64`, поэтому в батч влезает
  много и всё считается быстро.

**`full_pipeline_docs_per_sec`: 74.6 док/с — скорость всего пайплайна.**
Это классификация **плюс** тегирование. Ниже, потому что узкое место —
тегирование:
- **spaCy работает на CPU** (малые модели `_sm` не ускоряются на GPU);
- **spaCy обрабатывает тексты по одному**, без батчинга.

Аналогия: быстрый станок в начале конвейера (BERT, 1384/с) не помогает, если в
конце один медленный участок (spaCy) обрабатывает детали поштучно.

**Какая цифра отвечает условию:** порог «>=100 док/с» относится к классификации
(на это указывает подсказка про батчинг) — и берётся с запасом (1384). Полный
пайплайн (74.6) указан для честности. Его можно ускорить выше 100 батчингом
spaCy через `nlp.pipe()` и отключением лишних компонентов (оставить только NER).

## Классификация и тегирование — это разные движки

- **Классификация** — дообученный DistilBERT (нейросеть). Одна категория на весь
  документ из закрытого списка 18 сценариев.
- **Тегирование** — spaCy + NER (отдельный движок). Много тегов: сущности
  (имена, даты, места, организации) + ключевые слова + категория как контекст.

Это две независимые подсистемы, работающие над одним документом.

## Как запустить дашборд (локально, на маке)

Дашборд облегчённый: не требует torch/transformers. Живая классификация — через
бейзлайн (лёгкий), тегирование — через spaCy. Всё в терминале, в папке проекта.

### 1. Зайти в папку проекта

```bash
cd ~/Documents/document-categorization        # подставь свой путь
```

### 2. Установить зависимости

```bash
python3 -m pip install --user streamlit pandas
python3 -m pip install --user scikit-learn         # для живой классификации (бейзлайн)
python3 -m pip install --user spacy                # для живого тегирования (опционально)
python3 -m spacy download en_core_web_sm           # модель spaCy (англ.)
python3 -m spacy download ru_core_news_sm           # модель spaCy (рус.)
```

> Используем `python3 -m pip`, а не просто `pip` — на маке команда `pip`
> часто отсутствует, а `python3 -m pip` работает всегда.
> Флаг `--user` ставит пакеты в пользовательскую папку (не требует прав
> администратора — важно на общем/лабораторном маке).

### 3. Положить модель бейзлайна (для живой классификации)

Файл `baseline_tfidf_logreg.joblib` должен лежать в `models/checkpoints/`.
Он генерируется в Colab (`train_baseline(...).save()`) и скачивается на мак.
Без него дашборд работает, но раздел живой классификации показывает подсказку.

### 4. Запустить дашборд

```bash
python3 -m streamlit run app/real_time_dashboard.py
```

> Запускаем через `python3 -m streamlit`, а не просто `streamlit` — короткая
> команда может быть не в PATH. `python3 -m streamlit` работает всегда.

После запуска в терминале появится адрес `http://localhost:8501` — дашборд
откроется в браузере автоматически (или открой адрес вручную).
**Остановить:** `Ctrl + C` в терминале.

### Если что-то не запускается

- **`command not found: pip`** → используй `python3 -m pip ...` (см. выше).
- **`No module named streamlit`** → streamlit стоит в другом Python; поставь его
  в текущий: `python3 -m pip install --user streamlit`, либо используй
  виртуальное окружение (ниже).
- **`command not found: streamlit`** → запускай через `python3 -m streamlit run ...`.
- **Ошибка про `.pyё` / странный символ** → в конце команды случайно попал
  лишний символ (напр. русская «ё»); перепечатай, оканчивая ровно на `.py`.

### Надёжный вариант — виртуальное окружение

Убирает всю путаницу с разными Python на маке:

```bash
cd ~/Documents/document-categorization
python3 -m venv .venv
source .venv/bin/activate
pip install streamlit pandas scikit-learn spacy
python -m spacy download en_core_web_sm
python -m spacy download ru_core_news_sm
streamlit run app/real_time_dashboard.py
```

Внутри активированного `.venv` команды `pip` и `streamlit` работают напрямую.
Папка `.venv` в `.gitignore`, в репозиторий не попадёт.

## Обучение модели (в Google Colab с GPU)

Дообучение DistilBERT тяжёлое — запускается в Colab на GPU:

```python
# 1. свежий код с GitHub
!git clone https://github.com/seitenovagulnara-code/document-categorization.git
%cd document-categorization
!pip install -q transformers datasets

# 2. обучение (несколько минут на GPU)
from utils.data_loader import get_train_val_test
from utils.transfer_learning import train, evaluate_transformer
splits = get_train_val_test()
model, tokenizer, trainer = train(splits)

# 3. метрики по языкам
print(evaluate_transformer(model, tokenizer, splits))
```

Обученная модель сохраняется в `models/checkpoints/` (и на Google Drive, т.к.
Colab-сессия временная). В git модель не коммитится — она тяжёлая и
воспроизводится кодом.
